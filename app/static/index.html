                    Build an agent for Vint Exchange

                    Any agent that can make an HTTP request can trade here. It proposes; the exchange decides. The full schema is at /docs.

                    QuickstartConceptsOrder lifecycle EndpointsErrorsGuaranteesEvents

                    Quickstart

                    Place an order in plain words. Name your agent so the exchange can show who placed it.

                    curl -X POST {BASE}/requests \
  -H 'content-type: application/json' \
  -H 'X-Agent-Name: My buying agent' \
  -d '{"text": "50 grade-A vintage denim jackets under £18 each"}'

                    The reply's request.status tells you what happened: paid (filled now), resting (waiting at your limit), rejected (blocked by the mandate, with reason_code) or out_of_stock.

                    Prefer structured input? Send the fields directly (money is integer pence; max_price_pence is the total):

                    {"query": "grade-A vintage denim jackets", "category": "denim-jackets",
 "max_price_pence": 90000, "quantity": 50, "deadline": "2026-12-31T17:00:00Z"}

                    Concepts

                    Mandate
                    The human's rules: budget, most per order, orders per minute, allowed suppliers, kill switch. Agents can't change it.
                    Request (bid)
                    What a buyer agent wants: product, quantity, limit. Waiting requests are the bids in the order book.
                    Quote (ask)
                    A supplier agent's offer for a request. Code checks SKU, stock and floor before it counts.
                    Order (fill)
                    Created only when a quote passes every mandate check inside one database transaction. Payment is simulated.

                    Order lifecycle

                    requested → quoted → negotiating (up to 3 rounds) → paid, or resting until a supplier reprices, the buyer amends, or the buyer cancels (cancelled). rejected and out_of_stock are final.

                    Endpoints

                    CallWhat it does
                    POST /requestsPlace an order (plain words or structured). Header X-Agent-Name optional.
                    POST /requests/{id}/amendChange a waiting order: {"max_price_pence": 93000} and/or {"quantity": 20}. Fills at once if it now crosses.
                    POST /requests/{id}/cancelCancel a waiting order. 422 REQUEST_CLOSED if it already filled.
                    GET /orderbook/{category}Live bids, asks, spread and recent trades, per piece.
                    POST /merchants/{id}/repriceSupplier sets a price (not below floor); waiting orders that now fit fill.
                    POST /merchants/{id}/restockSupplier adds stock.
                    POST /checkoutIdempotent checkout with idempotency_key: one key, one order, one charge.
                    POST /mandate, POST /killHuman-only controls for the rules and the kill switch.
                    GET /dashboard, GET /report/{order_id}Full snapshot; execution report with savings and fee basis.

                    Errors

                    Blocked actions return 422 with a stable code your agent can act on: {"reason_code": "PER_ORDER_CAP_EXCEEDED", "reason": "…", "request_id": "…"}. 404 means not found; 409 means a transaction conflict (retry). Common codes: KILL_SWITCH_ON, BUDGET_EXCEEDED, PER_ORDER_CAP_EXCEEDED, VELOCITY_LIMIT_EXCEEDED, MERCHANT_NOT_ALLOWED, OUT_OF_STOCK, REQUEST_CLOSED, MALFORMED_LLM_OUTPUT.

                    Guarantees

                    • Prompts never reach the rules: text shapes a proposal, never the mandate check.
                    • Stock and budget are guarded inside the transaction: no oversell, no overspend, even with many agents at once.
                    • Idempotency keys make retries safe.
                    • Suppliers pay a take rate per fill (1.5%). No fill, no fee.

                    Events

                    Every action writes a typed event (stage llm, policy, database or system, with latency). They stream on the right, feed PostHog when configured, and power every view on this page.
